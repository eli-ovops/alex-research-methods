# Liquity WETH 直接清算：最小方案的协议条件与影子验证边界

本稿只提出可审阅条件，未实现适配器、未请求链状态、未运行 ABI/EVM、未执行策略或交易。结论是：**已封 V2 源码支持个人直接调用公开清算入口，不要求调用者偿还整笔债务或使用 flashloan；一次影子观察可检验自己是否能完整、及时地形成候选，不能证明个人净利润或实际捕获率。** 当前具体 WETH 部署与这份源码/ABI的一致性，须由 Root 本轮官方资料绑定，不能仅凭旧地址或接口相似认定。

## 1. 直接入口及资本边界

`extracted-verified-TroveManager.sol` L417–475 的 `batchLiquidateTroves(uint256[])` 是 public，所读入口无 caller 白名单或债务转入要求。L429 在执行中重新调用 `priceFeed.fetchPrice()`；L434–438 使用协议 Stability Pool 的 BOLD，L443–453 处理 offset 与再分配。L343–392 说明 SP 不足时剩余债务/抵押物可重分配，并非要求外部清算者补足。L537–544 从 GasPool 转 WETH、从 ActivePool 发送抵押物，收款人为 `msg.sender`。

因此最小路径可限定为 **EOA→这一 WETH TroveManager→同一 EOA 收补偿**，无需复刻十月 H helper。需要原生 ETH 支付网络费及失败尝试，不等于零本金/无风险。若日后为竞争另加 helper、私有发送或直接区块付款，须另列实际成本；不能把十月付款比例套到直接入口。

资格为 active 或 zombie 且 ICR 严格小于分支 MCR（L478–506），不是 V1 Recovery Mode 的筛选规则。只剩一个 trove 时清算可触发 `OnlyOneTroveLeft`（L1187–1190、1501–1505）；无实际可清仓位会 revert `NothingToLiquidate`（L440–442）。候选符合 ICR 条件仍非保证成功。固定补偿逐成功仓位累加（L522–535）；可变补偿基于 SP offset 对应抵押物部分，非任意整仓抵押物的固定比例（L334–392）。本稿不计算任何预算、奖励或利润。

## 2. ID 全集、按块更新及最小对照

初始块 B 必须固定 chain、TM 地址、区块号及 hash；在同一 B 上读 `getTroveIdsCount()`，再完整读取 `getTroveFromTroveIdsArray(0..N−1)`（L218–223），检查数量、唯一性和块身份。数组存活 ID 包含可清算的 zombie；关闭用 swap-and-pop（L1136–1150、1501–1508），所以数组下标不是持久 ID，跨块分页会遗漏/重复。

每个观测块应得到完整 ID 集及该块的 status、latest entireDebt/entireColl，不能只刷新有单仓日志的 ID：利息、批管理费、全局再分配和 oracle 变化可在无本仓操作时改变资格（L943–1013）。最小正确基线是每个选定 B 完整重读；若用事件增量优化，须先核全套开/关/批处理/重分配事件语义并以同块全集校对。该事件状态机尚未适配，不能宣称已完整实现。

V2 `SortedTroves` 按借款人年利率排序（该文件 L15–25），且关闭逻辑区分 active 链表与 zombie（TM L1512–1533）；不能把链表尾当最低 ICR 或作为全集。官方旧 `liquity/liqbot` 是 V1，原版本准入结论已经关闭直接复用，不重开。

**对照应服务数据/时序检验**：对同一预先固定观测块，用完整 ID 快照作为增量扫描的校验全集；记录每个集合差异及原因。资金相同或扫描到别人成功交易不是本轮净收益对照。若资源只够离散块，明确称“离散块影子观察”，不把未观测块计作没有机会。

## 3. 事前信息与真实 oracle 路径

对 B 的数据，最早本机可用时点是实际收到 B 及必要响应之后，必须保存请求发起/完成、区块/日志通知到达、完整候选形成的 UTC/单调时钟，区块 timestamp 不替代本地接收时间。B 内已经完成的赢家是结果资料；不能把包含该交易的 B 末状态/事后事件当作我们在 B 内可用的信号。最早拟执行窗口只能在完整信号形成之后，不能凭 B+1 价格或赢家倒填 B 候选。

`getCurrentICR(id, price)` 使用调用方给的 price（TM L943–946），并不认证清算时使用的价格。WETHPriceFeed L19–44 根据 `priceSource` 走 Chainlink ETH/USD 或 `lastGoodPrice`；MainnetPriceFeedBase L53–75、78–124 检查 latestRoundData 的成功、answer、updatedAt、新鲜度及精度，异常可关停并切换 lastGoodPrice。应在同一 B 留存 priceFeed/aggregator 地址、priceSource、lastGoodPrice、shutdownTime、round/answer/updatedAt/精度与 staleness 参数；外部交易所价格不能代替该路径。不能只缓存“最近一个 oracle 事件”而忽略故障/陈旧路径。

B 状态上的资格只能标作“B 时点条件候选”。实际入块时会重新取价，借款人操作、其他清算、SP变化、利息、时间及重组均可能改变结果。若以后采用只读模拟或估 gas，也只能记该块/调用上下文的结果和假设，不能升级为未来保证；本轮未做此类调用。

## 4. 一次影子观察的通过、停止和不可判定

Root 应在任何新观察前冻结分支/部署、未来起止、取块节奏、确定性 ID/候选选择顺序、源与调用/时限/磁盘上限，不按发现奖励续期或换样本。先以一个完整固定块核验字段与资源消耗，再决定预算内可覆盖的观测块数；不能预称免费档足以每块遍历未知 N。全过程只记录，不发送交易。

可通过的最窄结论：指定范围内 ID 集完整、响应块一致、oracle 路径可解释、本机确能在结果发生前形成候选记录。可证伪：数据缺字段/混块、ID遗漏、预算内无法完成扫描、信号形成时该候选已被处理等。拒绝/配额/缺页/重组未能校正即停止受影响记录并保留原件；缺失不补零。若窗口没有候选，只能报告该窗口未观察到候选，不判服务整体失败；观察不足或成本/入块未知则经济结论不可判定。

**影子观察不产生实际捕获率**：他人成交成功数是被选中的结果，包含对方私有信息、发送路径、优先级和竞争；没有我们提交的请求、接受/拒绝/重试/入块/失败记录，不能作为我们的成功次数或分母。即使候选持续到后续块，也仅说明它未被这些可见状态更新消除，不证明我们会入块或获奖。零交易不能通过“个人完整扣费正净利”门；它最多支持是否值得提出下一项有明确范围的执行验证方案，本轮不授权该执行。

## 5. 最小适配缺口与记录字段

缺口限于：当前 WETH 部署/registry/ABI/oracle/SP/token身份绑定；V2 ID 全集及同块读取；latestData/批仓/全局变动适配；oracle 路径；本机到达时间与重组处理；确定性记录。无需旧 bot 私人选单逻辑。许可应按文件/用途分别核，公开调用资格不等于任意复制核心源码许可。
