# Liquity 清算服务：个人全成本优势的最小验证方案

版本：V1，2026-10-20。状态：**方案，未执行**。本轮仅研究和制订方案，未实现采集器、调用链状态、模拟执行、连接钱包或发送交易。

**建议只验证这一件事：普通电脑和免费数据通道，能否及时发现 Liquity WETH 清算任务，并由个人直接完成后，在失败费、竞争成本和必要劳动全部扣除后，比同起点不运营留下更多钱。** 不再训练价格预测模型，不复制私人机器人，也不将别人成功的交易重放成我们的利润。

这项服务的付款方是协议内被清算仓位的补偿安排，收入是完成清算的报酬；竞争者可能通过更快的数据、发送和竞价拿走报酬。机会来自协议需要外部人执行任务，**并不意味着公开机会天然留有个人利润**。官方资料列有固定 WETH 补偿和抵押物补偿，具体支付仍取决于版本与处理路径。[官方 FAQ](https://docs.liquity.org/v2-faq/borrowing-and-liquidations)、[官方源码及机制说明](https://github.com/liquity/bold#liquidation-and-the-stability-pool)

## 1. 一条规则，分清两道证据门

| 门 | 固定工作 | 能回答什么 | 不能冒充什么 |
|---|---|---|---|
| A：先筛可达性与经济空间 | 未来连续14日，只读记录本机实际收到的数据、候选和后续结果；不签名、不广播 | 免费条件下能否在任务被处理前形成完整候选；观察状态的账面空间是否值得继续 | 我们实际获胜、实际失败费、个人净利润 |
| B：个人全成本检验 | **只有另获明确授权且适用条件满足后**，按固定规则做有损失硬帽的实际执行原账核验 | 本人这段期间是否真正获得全成本正增量 | 稳定未来优势、扩大本金后的收益、财富目标可达性 |

这是一个服务假设的两道门，不是同时启动两个项目。A显示的账面空间为负，可按研究预算结束，但不是对真实执行收入的严格否证；A为正仅得到“值得考虑B”的候选。**在坚持不执行交易的条件下，无法把本人抢单成功率和失败支出从假设变成事实，因此不能宣布通过B。** 本轮不授权或启动A、B。

## 2. 固定对象和决策规则

只研究 Ethereum 主网、Liquity V2 的一个 WETH 分支，候选为既有十月案例的 TroveManager `0x7bcb64B2c9206a5B699eD43363f6F98D4776Cf5A`；必须先核它与官方部署和当前代码的一致性，未通过就停止，不临时换地址。采用直接公开清算入口、一次一个 Trove（借款仓位）。不做 Stability Pool 存款，不做 JIT 债务垫资，不用闪电贷、私人 helper、私有订单流或额外区块付款。

已存版本支持公开 `batchLiquidateTroves(uint256[])`，协议池承担债务抵销；这不是要求执行者拿出整笔借款本金的服务。**采用全额 Stability Pool 覆盖路径**：同块可用余额扣除该版本要求的保留额后，足以覆盖目标全部债务；混合抵销、再分配和其他路径全部记录但不参与本次候选。不得把通用补偿公式机械套用到所有路径。[官方机制与条件](https://github.com/liquity/bold#liquidation-and-the-stability-pool)

未来执行前的必要预检限于：官方部署身份与当前代码/ABI、WETH及依赖地址、准入与停机状态、补偿和池保留额、真实 oracle（协议采用的价格来源）与债务计算。本轮读取的旧源码不等于已认证当前运行部署。若不一致，停止本版方案，不临时换分支或改规则。

未来A的 T0 在预检完成后、查看新观察结果前写死，结束为 T0+14日。按每个新接收到的区块触发扫描；处理不过来就标缺失，不拿旧状态装新状态。完整快照包括 active 与 zombie 仓位（后者虽不在排序链表内仍可能可清算）。V2排序按利率，不能从链表尾当作风险最差仓位。

候选须同时满足该版本全部清算资格、全额池覆盖、数据完整和发送成本约束。每个UTC日，首次出现符合全部条件的快照时，多个候选按**当时可见的最低补偿减支出上限**降序，ID升序破同分；不等到事后挑当天最赚钱者。未来B一次只允许一个未决交易、一次一个仓位，每风险簇至多一次尝试；没有符合费用帽的机会就不尝试。资格在实际执行时会变化，前一块可清算不保证下一块成功。

**去重和聚簇机械定义：**以`chain＋分支＋Trove ID`识别仓位；连续“协议资格成立且全额池覆盖”的完整观测是一个资格episode，起点为首次因果可用的合格快照，终点为首次同块完整证据显示资格不成立、已关闭或已清算。数据空档标UNKNOWN，不能用它结束旧episode再制造新机会；恢复后须先有完整不合格快照，再次进入才算新episode。episode跨块、跨UTC日仍是同一个。同一episode仅第一次同时达到费用与完整性条件时可参与候选选择；一旦获选或放弃，其后不重新参与。将首次参与选择在同一UTC日的全部episode合并为一个**风险簇**，本版每簇/实际发送UTC日均最多一次尝试。A按相同选择规则记录虚拟决策但不作成交；B的簇数按形成候选并作选择的日期计算，不按赢家数量计算。连续日期仍可能相关，日簇不等于统计独立。

## 3. 数据：用我们当时知道的资料，而不是赢家的事后答案

数据使用官方合约的正常公开只读接口、区块/日志/收据和本机时钟；用户已有免费 Alchemy 账户仅是候选通道，**本轮未使用其凭证或验证实时接口**。部署与ABI先绑定；完整ID全集须在同一区块号和hash上枚举。批量读取可降低开销，但不能只用会遗漏 zombie 的排序 getter；读聚合器也须先核身份，不部署新合约。

必须保存以下原件及字段，分页、错误、停机和未采用记录也保留：

- **身份与时序**：chain、部署/ABI版本、区块号/hash/parent、请求发起/返回与候选形成的UTC及单调时钟；区块timestamp不能代替本机收到时间。用不同运营方的正常公开区块源校对身份与延迟，不能把这种校对称为已测全球最快通道。
- **同块资格**：完整ID/status、计入应计利息与相关调整的债务/抵押物、协议oracle路径、池可用额、MCR（最低抵押率）、停机标志和排除理由。不能用交易所现价代替协议oracle，也不能跨块分页拼全集。
- **机会全过程**：发现、候选形成、放弃原因、后续被谁何时处理、重组及最终确认。包含未发现的公开完成事件与全部采集空档；不可观测期间不填0。
- **若以后到B**：全部提交/拒绝/未入块/成功/失败/替换/取消，hash、nonce、收据、奖励实际归属、全部付款、期初期末资产及所有者资金流。不能只交成功交易清单。

包含在区块B里的清算，若我们收到B以后才知道，明确记为**已错过**；不能把它算作可抢到。候选在后来一块仍存在，也不等于我们的交易会入块。六月、十月旧案例只用于核对字段和成本类别，不并入新的独立样本，不用他人成功数估计我们的成功率。

## 4. 对照与完整费用账

**唯一主对照：同起点、相同ETH/WETH和现金、相同所有者投入/提取，但不运营清算服务。** 未使用部分现金保持同样处理，不用另一钱包同时竞争。共同持有ETH的涨跌从对照中抵消；新增奖励之后的持仓涨价另列，不能把负经营贡献改成“服务优势”。

主指标是固定发生时点、一致计价的**税前全经营成本净贡献**：实际可归属奖励，减全部执行费用、必要新增搭建/维护劳动、基础设施、结算和额外资本成本。ETH/WETH数量账、按发生时点折算的美元经营账、期末盯市的净资产对照三者分别报告并勾稽，不混成投资回报率。历史研究沉没成本不重算为本次搭建费。

| 必扣项目 | 防止漏项或重复 |
|---|---|
| 所有已入块交易的实际网络费 | 成功和失败都扣；`gasUsed × effectiveGasPrice`已含基础费和优先费，内部gas不再另扣。替换/取消按实际入块收据收费，不给所有未入块版本虚构gas。 |
| 直接付款、relay/融资等实际费用 | 本版规则不使用额外竞价付款；一旦出现未声明的收费或支出，不能填0。旧十月案例的付款比例不套给我们。 |
| 包装/解包、转入转出和结算费用 | ETH↔WETH是转换，不是又一笔收入；实际网络费和兑换价差分别入账。不强求卖成美元才能核期间损益；若称“到账美元”，才须实际兑换腿。 |
| 必要新增搭建和运维劳动 | 主账全额计本次必要新增成本；规划默认机会时薪**20美元/小时**，是透明的研究假设，不是已知薪资或实际新增付款。记实际工时，不为过门槛事后摊到无限未来。 |
| 基础设施、资金占用 | 免费额度只把实际账单记0，劳动不免费；同一资金机会成本若已包含在持有基准中，不重复扣。 |
| 税及尚欠款项 | 税单列，适用口径未知保持UNKNOWN；本方案不把税前利润写成税后个人到手。未结算但已承担的费用预提；关键费用无法给可信上界时，全成本结果不可判定。 |

A只做**观察状态的乐观账面情景**：对固定规则首次选中的候选，暂假设每风险簇中一次，用形成候选时可见的补偿和费用估计扣除必要固定成本，暂将失败、竞争支出归零。不能重复累加跨块同一episode，不能事后选全日最高奖励。实际执行的状态和费用可能改变，所以这**不是实际收益，也不是实际收益的严格上界**。情景为负，仅表示本次资料不足以支持进入B、可按预算停；情景为正也不能证明能抢到或能赚钱。没有完整收入上界、费用下界和可执行状态覆盖证据，不作经济不可能结论。

当期主账全扣开办成本，是在检验本次个人参与是否划算，不代表经常性运营永久亏损；另列一次性与经常性账。可以报告按本次实测单任务净额回收开办成本需要的任务数量，但不得假定未来有这些任务，或将未发生的任务摊销成已盈利。

## 6. 通过、未通过、不可判定、停止

**A通过仅是数据与候选门：**预定观察窗口的覆盖、全集、版本、oracle与本机时序可核；至少一个候选确在被处理前形成，相关状态和费用预估可复核；固定观察情景的账面空间为正。它不通过“净盈利门”。若有覆盖缺口，仅逐条承认已核候选，不能宣布完整窗口通过。

**B1：完整当期正账成立。**所有机会和尝试、所有者资本流与费用账完整，在20美元/小时劳动机会成本假设下，税前主经营净贡献>0，同起点净资产对照扣除未入账费用后增量>0，且没有预算违约。即使只有一次成功，也保留这个有限历史正事实；不把它升级为稳定优势。

**B2：保留为继续研究候选。**在B1上，至少3个分属不同UTC日的风险簇产生成功，且去掉最大一项奖励后，仍扣原有全部成本，净贡献仍>0。后两项是防单笔运气的固定保守筛查，**不是独立性证明、显著性检验或稳定获利认证**。未达B2不回写B1为失败。

最多10簇、14日可能远不足统计识别。本最小方案不预设不存在的独立同分布条件，不给小样本包装95%确定性：即使B2通过，也只称“本人在固定期间出现可复核全成本正增量，保留候选”；**持续优势与未来容量仍未证明**。税务和本人真实替代时薪未核，也不称税后个人到手优势。以后要更强结论，须另固定独立前瞻窗口，不得在本次结果上反复择优。

- **未通过/本轮不进入下一门**：A观察情景为负则不进入B，不作经济否证；B完整原账成立但全成本经营净贡献不正，则B1未通过。若B1正但未达去最大赢家等B2门槛，保留正账事实，持续优势仍不可判定，不抹掉历史正数。
- **不可判定并到期停止**：没有机会、样本过少、错过全部任务、关键成本或状态缺失、覆盖不完整。不能把它写成清算服务永远无效，也不能因此自动续期。
- **立即停止受影响阶段**：费用/资源帽触发、需新付款或新增权限、来源明确拒绝、代码/规则身份不匹配或改变、无法校正的混块/重组/陈旧数据、账与资金归属无法闭合。保存已获原件，不改门槛重跑，不自动进入B。

## 7. 最后必须交付的四个数与容量边界

只读A交付：完整覆盖比例、事前形成的episode/风险簇数、已错过/未知数、扣必要固定成本的观察状态账面情景。本人获胜与净利润明确留未验证。

若以后B执行，交付：①全机会→实际尝试→成功漏斗；②全成本净贡献及同起点对照；③去最大赢家结果；④每单位投入劳动的净贡献，并分别列开办与经常性成本。不得用成功交易的平均奖励代替整段服务的净收入。

**资金容量来自任务量、可获得份额与每笔剩余报酬，不来自把5000美元乘大。** 本次只测这个小配置；14日零/少任务不能证明全市场没需求，几次成功也不能外推十倍资金。要扩大，仍缺跨行情需求、竞争加剧后的可获份额、更多并发/报价支出下的净增量和维护成本。没有证据能把它推成Gerko财富1%的路径。
