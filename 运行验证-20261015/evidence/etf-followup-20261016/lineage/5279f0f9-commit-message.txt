* etfs README: say 'baseline backtest', and stop implying the paired statistic is a subtraction

Two corrections to the rewrite in ca16e5d5, both raised by the pre-push review.

AGENTS.md bans 'signal stage' project-wide - stage='signal' IS the baseline
backtest, and the stored enum is not prose. The rewrite used 'signal-stage
Sharpe' twice and the pre-existing intro used it once; all three now say
'baseline backtest'. The intro's claim that the LSTM holds the highest such
Sharpe is corrected with it: the registry has gbm at +0.83 against sequence DL
at +0.82.

The holdout paragraph put +0.232 and +1.358 next to a difference of -1.221, which
reads as a subtraction and is not one - those two subtract to -1.126. The -1.221
is a paired statistic computed on the two series' common support with a
21-period bootstrap block over 2,000 resamples, and the text now says so.

Added while correcting it, because it changes how the holdout should be read: the
same paired comparison on validation is +0.559 [-0.021, +1.061], p=0.044. Its
lower bound was already below zero before the holdout was opened, so the strategy
never cleanly beat equal weight even on the window it was selected on.

* test_etf_checkpoint_contract: compare the reduction to what the notebook declares, not to a copy

test-unit failed on PR #694 at

  assert parameters['PREVIEW_REDUCTIONS'] == {'folds': [0, 1], 'max_symbols': 5}
  AssertionError: assert {'folds': [0, 1]} == {'folds': [0, 1], 'max_symbols': 5}

because 10_dl_tsmixer dropped its max_symbols in 5d9c9446 under #988.

The assertion was a transcription of overrides.yaml, which is what this test's own
docstring says it was rewritten to stop being: 'This asserted the pre-conversion
names, so it was checking a transcription of overrides.yaml that the file had moved
past.' It fell back into the shape it documents, and the two notebooks it loops over
no longer reduce identically, so a single hardcoded mapping cannot describe both.

What the docstring says the test is for is precedence - that _quick_parameters does
not overwrite what the notebook declared - and that is checkable without copying the
value: compare the returned reduction to the notebook's own declaration. The
invariant worth keeping alongside it is that the declaration is non-empty, since a
converted notebook that reduces nothing is a canonical run wearing the wrong tier
and the request builder refuses it.

The test now fails if _quick_parameters clobbers a declared reduction, or if a
notebook declares none. It no longer fails when the fixture legitimately changes.
