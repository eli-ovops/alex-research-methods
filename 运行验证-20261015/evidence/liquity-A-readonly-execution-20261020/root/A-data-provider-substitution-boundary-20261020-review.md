# A 数据供应商替换边界：只读独立审阅

结论：**Alchemy 是原 A 的候选数据通道，不是科学假设或用户授权中不可替换的供应商。** 当前源码确实只接受 Alchemy，但这是实现的安全白名单和费率绑定，不能倒推为研究必须使用它。合法独立 Ethereum 公共 provider 的官方资料准入，是当前可推进的必要只读工作；不必先修好 ClashFX，也不因一条通道失败就将整个目标判为 blocked。新 provider 尚未准入，本稿不授权运行、换 URL、输入凭证或恢复旧进程。

原方案 §3 直接写“用户已有免费 Alchemy 账户仅是候选通道”（L34），目标写的是普通电脑和免费数据通道（L5）。原方案“本轮未使用凭证”等表述属于当时 V1 历史快照，不冒充今天状态。后续技术失败与曾经 ARMED 的证据仍保留；据本次任务现状，正式 T0 尚未开始、14 日正式样本为 0，不能把预检当正式样本。

## 哪些是管道适配，哪些会改变试验

**可以作为原 A 必要技术适配处理：**明确新的合法官方 endpoint/HTTP 与 WS 方法和参数、schema/体积与 gas 上限、认证形态和脱敏、固定安全路由、免费限流/订阅计量，重绑源/配置/发布身份，旧 run 保留并用新隔离 run/once。只要取得相同因果信息、覆盖与全部门不放松，这是同一研究对象的通道改变，常规零费步骤不因“换 provider”再造逐步人工批准。

但当前不能只改一个 URL：core L11/L66–82 将 HOST、`/v2/...` 路径和脱敏/隐藏输入写死，CONNECT/SNI 同样固定；binding 的 `rpc_CU`、`stream_CU_per_byte`、quota/billing source 也属 Alchemy。未来必须整条安全/方法/收费接线一致，并有精确发布与新通道预检；旧 release 不可直接放行新来源。若新入口不需 key，就不人为增加账号依赖；若确需本人凭证，仍仅本人本机隐藏输入，不读取/传递旧 key。独立 provider 不是旧明确拒绝资源的镜像/代理取回，旧拒绝边界仍有效。

**不能悄悄作为换通道处理：**换链/分支/代码或 oracle、缩减仓位全集/采样频率/完成事件、改变时效门/资格/费用假设/候选排序、移动 T0/T1、拼接不同时期或来源择优数据、引入自动重试/重连/丢消息补洞、扩大硬帽/新增付款/账户权限、执行 B 或交易。若需这些变更，须先明确协议差异、授权和新结论范围，不能沿旧 PASS 冒称同一完整实验。没有 WS 也不能偷换成粗轮询后宣称原逐头及时性已测；等价设计若有，必须另行明确并验证完整性，当前未证明。

## 新供应商最小准入未知

最关键问题是：**其合法免费入口是否同时支持整个原 A 所需的同块读取、完整响应及新区块通知，并能在既有资源帽内持续取得。** 不是先问它能否“赚钱”，也不是只验证一个 `eth_call`。

官方资料只需补足影响准入的字段：Ethereum chain/部署支持；HTTP/WS及可用方法；hash 固定状态参数与历史状态/重组语义；Multicall 所需 gas/请求及响应体积上限；logs 分页/范围；免费入口认证/条款及拒绝处理；RPS/并发连接/订阅/流量/请求或 credits 额度与重置周期、超额行为及零付款控制。免费无 SLA 是未保证，不能直接判不能研究；反过来也不能把所有方法、订阅或流量无证视免费。资料齐后仍需本轮之外按授权实际预检，文档不是实测时效或 14 日通过。

**单位不能混：**Alchemy 的 25M CU、26 CU/call、0.04 CU/byte 和本地吞吐刻度不等于 dRPC 的实际计费单位/免费额度。保留旧 Alchemy 累计账并分列新 provider 自身请求/流量/credits；不得直接相加异质单位、把新免费池作为旧账清零，或把旧 25M 当成新服务余额。若要保留旧 CU 作为额外项目工程刻度，Root 须在新数据前明示其映射/费率版本和“非供应商账单”含义；新的实际免费/RPS/连接/订阅限额同时从严。不能定义可信计量或无法满足全量资源门时，不准入该配置，不据此否定所有免费数据或清算经济。

当前 binding 的 shared_prior_usage 为失败前 32734 CU/62 methods 快照；本次已知后续停止保留的是 32734 CU/63 methods，不能把 62 当最新量。最新累计 CPU/人工/其它新增资源由 Root 当前账绑定，本稿不重算、不重置或替它补造。

合理路径是完成正在进行的独立官方 provider 文档准入，再决定是否有满足全部门的最小通道适配。没有证据要求把 ClashFX 修复作为必经步骤；本稿也不预判 dRPC 已合法可用、已免费或已具备完整 A 能力。保留原历史正账和经济不可判定，不改 AAPL/Kronos 或借用其“同供应商”规则。
