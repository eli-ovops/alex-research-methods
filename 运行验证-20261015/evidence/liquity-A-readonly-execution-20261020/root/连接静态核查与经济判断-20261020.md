# 当前决定

暂不继续盲改采集器或重复索取RPC输入。现有代码核查未找到能解释本次TLS握手超时的已证实现缺陷；当前需要定位本机代理的安全日志入口，才能取得更有区分力的证据。

## 新取得的结论

1. 成功准备、RPC和公开探针使用同一连接方法、固定SNI和严格证书校验。CONNECT逐字节解析，没有发现吞掉TLS数据的实现证据；失败发生在新连接握手中，连接复用不是该次触发因素。
2. 15秒是总请求预算，单次握手I/O仍最多5秒。该差别确实存在，但不能因此认定放宽超时就能修好。当前不修改该策略。
3. Root只读系统获准字段确认HTTPS代理启用、PAC关闭、回环路线符合原规则；可见监听器查询未返回记录，不能据此宣布代理未运行。当前软件身份、日志入口及上游失败原因仍UNKNOWN。未读取应用日志、配置秘密、argv、环境或剪贴板，也未发网络请求。
