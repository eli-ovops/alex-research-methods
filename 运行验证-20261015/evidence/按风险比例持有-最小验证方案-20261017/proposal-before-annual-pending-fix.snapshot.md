# 按风险比例持有：最小验证方案

**只比较一个问题：原60日波动调仓规则，在实际风险相近时，是否比每年只调整一次、年内持币不动的BTC＋现金对照更好？** 当前仅冻结文档，不实现、不计算新市场结果、不运行回测或交易。通过也只形成值得进一步验证的历史候选，不能证明可复制盈利或Gerko财富目标。

## 1. 单一窗口与已知历史

固定2014-01-01 00:10 UTC入场，连续到2025-12-31 00:10 UTC清仓。全期仅一个初始5000 USD账户，不按年或旧TRAIN/VAL/TEST重置，也不在2019/2022停仓。最后持有区间从2025-12-30到12-31，不包含之后行情。所有年份完整展示，不挑风险相近或盈利年份。

既有2020–21、2023–25成绩已看，规则也因旧结果胜出而被选择；2014–18同样已用于旧研究。把2019/2022纳入连续账不会产生真正新鲜样本外证据。这是**历史重用诊断**：本次先定公式，随后才计算新对照，但不是在市场发生前预注册。统计区间不能消除规则选择和本项目多次尝试的偏差。

数据只用既有Kaggle dataset1346/v755快照，CSV SHA256 `c5d5c392b3eeb24d5fc3bcbc4ef78b4e8ce005c84fede7e7fe0fee466c7e67b3`。优先复用既有日数据文件并对照原CSV身份；缺所需标签日、字段异常或文件身份不符即技术无效，不补数据、不换日期。历史修订、首次可得时刻、分钟开收端仍UNKNOWN。

## 2. 原规则不变；对照真持币

令每日标签23:59的Close为C_d，r_d=C_d/C_(d−1)−1；σ_d是截至d的最近60个r的总体标准差（ddof=0）。执行日e的信息截止D=e−2：

`v_e = min(1, 0.40 / [sqrt(365) × max(σ_(e−2), 10^−6)])`。

候选risk_scaled_buy_hold每天意图仓位就是v_e，不预测方向、不加趋势开关、不改60日、40%或滞后。

**唯一主对照annual_units_hold：** 每年首个计划执行日y-01-01，用该日之前的资料固定全年起始比例 `f_y=v_(y-01-01)`，亦即用截至上一年12月30日的60日波动。依同一自融资公式买入或卖出到f_y；之后全年保持实际BTC单位数及现金不变，直到次年1月1日才再平衡。年内价格变化自然造成比例漂移，绝不是每天恢复f_y。年度之间继承财富、BTC与现金，不每年追加5000，也不年末卖掉再于年初买回。全局终点额外清仓一次。

这是最小的“过去风险校准、随后直接持有”对照：共享原规则的过去60日风险预算，却不具有其每日动态调仓。**过去校准不保证未来同风险**，因此另设实现风险资格，不能用未来全年波动反推f_y、调资金比例或挑年份。没有第二个主对照；旧全仓BTC结果只作已知背景，不参与新检验择优。

## 3. 同一时钟、真实结转与费用

两组均以e日00:10标签Close为参考执行价P_e；仅使用e−2及以前信息决定意图。此为历史执行代理，并非可成交报价，不能证明当时已取得这些数据。现金利息0，无借贷、杠杆、空头，允许分数BTC。

参考分钟Volume=0：不成交，保留确切BTC单位和现金，保留该日期/估值/损益，不删失败日、不向后寻找有量柱。候选仅在下一计划日按原新意图再尝试；年度对照若年初未成交，则继续旧单位/现金，**不在年内补买**，下次仅次年1月1日。首年失败时可能整年现金，照实列明。正量也不证明能按Close成交相应规模。终点零量且仍有BTC时，不虚构清仓，不能报告完整已实现现金净利或PASS。

单边比例综合成本固定25bps主情形、50bps压力，包含假定手续费及点差/滑点，不再另加一次。不是本人实测成本，也不解决容量或无法成交。两成本复用相同意图规则/年度f_y，但分别继承其现金、BTC数量和漂移，不声称两路径持币相同。

每个计划交易时点：`V−=cash+u_old P`，`a=u_old P/V−`，目标w，`s=sign(w−a)`；`phi=(1+c s a)/(1+c s w)`，`V+=phi V−`，`u_new=w V+/P`，`cash_new=(1−w)V+`，费用`c |u_new−u_old|P=V−−V+`。无交易日直接结转单位/现金；no-fill同样不收费。首笔、年初/日常再平衡、全局末笔均扣费，末费只入最后一个收益区间一次，不重扣已计权益的费用。相邻日净收益按连续自融资权益算，不能用目标权重差替代实际换手。

## 4. 预定资格、主比较和结果分类

先完整封存两组、两成本的全部目标/年度比例和逐日账，再统一看所有统计，不途中窥看后改公式。仅一个全期主比较：25bps候选减年度持币对照。

**风险资格：** 两个成本下分别计算全期净日收益总体std×sqrt365；候选/对照波动比都须在闭区间[0.80,1.20]。任一不匹配或分母为0，即`INCONCLUSIVE_RISK_MISMATCH`，不事后缩放、剔年或换对照。年度波动也全部展示，但不逐年挑选或新增检验。全期匹配不代表各年风险、尾部风险、敞口或经济风险相同。

风险匹配且账务有效后，以下均满足才记`HISTORICAL_CANDIDATE_SUPPORTED`：

- 25bps候选末现金>5000；净Sharpe比对照至少高0.20，最大回撤不大于对照。
- 配对序列 `d_e=log1p(q_candidate,e)−log1p(q_control,e)` 的全期均值>0；固定90日循环区块bootstrap、10000次、种子20261017、单侧95%下界>0。每次两组使用相同日期块，拼接后截到原长度，5%分位用linear方法；只有这一项主比较，不重复更换块长、窗口或检验。
- 50bps候选仍净正、配对平均log差仍>0，Sharpe不低于对照且回撤不大于对照。压力结果不另做第二套显著性筛选。

账务有效且风险匹配，任一优势条件失败：`NOT_SUPPORTED_THIS_DIAGNOSTIC`；不是所有预测或交易机会不存在。风险不匹配优先记不可判定，仍展示全部结果，不把负结果藏掉。身份/时间/非有限数/自融资不闭合/终点未清仓：`TECHNICALLY_INVALID`；资源耗尽：`RESOURCE_STOP`，不冒模型无效，也不自动放宽或重跑。非现金组零收益std导致Sharpe未定义，不得PASS。

最大回撤只覆盖日估值/交易点。配对区块假设历史依赖可近似，跨年份非平稳和已选择规则使区间只具诊断意义。较高Sharpe、正超额或风险匹配均不能唯一因果分离BTC上涨、敞口调整、波动择时与alpha，也不保证个人可接受回撤。

## 5. 必须保存什么、何时停止

全期和每UTC持有区间年份报告：起末权益（非年末现金）、净额、总回报/CAGR、波动、Sharpe、最大回撤、换手、全部成本、平均/范围敞口、零量no-fill次数。年度沿连续账继承，不reset、不添加年界交易，末费只归最后年一次。另列两成本的风险比、全部通过条件和不确定区间；不得只给一条漂亮曲线。

逐日账保存P/信息截止/参考量、计划调仓标记、f_y或v_e、交易前后单位/现金/权益、实际漂移比例、费用/参考成交额、no-fill及末次清仓。校验现金恒等式、非负资产、成本扣一次和净收益连乘勾稽；沿旧容差`max(1e−8 USD,1e−10×权益)`，不静默修正。源/代码/设置/目标及两成本账先哈希封存，再评分；封存是本次计算内顺序，不是实时事前信号。
