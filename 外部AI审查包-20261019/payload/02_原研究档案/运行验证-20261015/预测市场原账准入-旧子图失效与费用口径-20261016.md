## 2．三个“V2”不能只按名字拼接

官方说明要求按市场版本选账本：市场v1使用Conditional Tokens与tokenId、交易域版本2；市场v2使用PositionManager与positionId、交易域版本3。名为“CTF Exchange V2”的代码或“Data API v2”，不自动表示市场已是Polymarket Protocol V2。当前合约地址清单也不是完整历史升级快照。[官方账本身份](https://docs.polymarket.com/resources/onchain-position-data)、[官方合约清单](https://docs.polymarket.com/resources/contracts)

余额应以ERC-1155的TransferSingle/TransferBatch重建；merge、Router、migration等事件提供业务上下文，不能再把同一数额当第二次余额变化。完整历史需从部署或可靠检查点开始，不能只读几条退出记录就称全历史。[官方事件说明](https://docs.polymarket.com/resources/onchain-position-data)

因此，合并取回100单位抵押物只证明该环节回款；利润还需减去对应权利的实际取得成本和相关费用。把本金回款当收入，或把同一动作的两种事件相加，会凭空制造利润。这是会计判断，不是对某个钱包的实测指控。

## 3．官方PnL字段也要读公式

| 字段或默认行为 | 原文核得 | 对研究的约束 |
|---|---|---|
| entry_cost_usdc | 不含费用的入场基础 | 不当成全部资金支出 |
| entry_fees_usdc | 归属BUY费用的披露字段 | 官方警告不要再从PnL列重复扣；仍须核其完整实现 |
| total_cost_usdc | 等于上述两项之和 | 仅此字段关系不证明网络、失败或全部经营成本已计入 |
| realized_pnl | 每个持仓累计的已实现PnL | 所读字段未给完整成本分配公式，不直接称个人全成本净利 |
| percent_realized_pnl | 兼容字段，公式不是realized_pnl除以本金 | 不能凭字段名报告实际投资回报率 |
| CLOSED默认排序 | 默认按已实现PnL | 用首行当样本会按收益选样；必须事前固定取样 |
| activity默认行为 | 省略出入金；必须显式关闭该排除 | “翻完返回页”不等于已包含全部资金流 |

来源：[官方钱包活动说明](https://docs.polymarket.com/trading/wallet-activity)、[持仓API参考](https://docs.polymarket.com/api-reference/wallet/list-positions-for-a-user-or-market)、[活动API参考](https://docs.polymarket.com/api-reference/feeds/list-account-activity)

这些是官方字段声明，不是本轮已用真实账户逐笔核平的结果。字段缺失或null保持UNKNOWN。也不能因为缺私人机器人，就否认另有完整原账可以证明某笔历史净收入。

另一个容易忽略的约束：当前trades参考说明，只有user路径使用start/end；全局、condition或event路径会按其自己的历史范围返回，忽略这两个时间参数。不能在全局接口上填日期后，就声称样本已按日期截取。分页游标还要求保留过滤条件，不能默认把返回一页当全量。[官方交易记录API](https://docs.polymarket.com/api-reference/feeds/list-trades)
